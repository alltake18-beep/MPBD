二、劇本如何產生

2.1 AI 定位：預知完整劇本的導演

劇本不是先指定輸贏再倒推。離線產線先固定所有合法隨機內容，再由預知完整固定種子的固定規則規劃器規劃並跑完整隻 Boss。它不是只看當下公開資訊的玩家視角 AI，也不負責預測未知玩家的真實行為分布。

預知不等於改寫：固定規則規劃器可以讀取同一固定種子的未來魔法卡、初始手牌、合法換牌結果、Boss 手牌、Boss 狀態與原始骰面；只能選擇合法操作，不能改內容、換種子、為了分類重跑，或在結果發生後回頭改寫先前操作。
1 固定種子星級、Boss、魔法卡、手牌、換牌序列、對手牌與原始骰面。
2 整隻規劃評估勝率、傷害、剩餘血量、成本、派彩與獲利機會。
3 合法遊玩決定保留、換牌、繼續或停損；第一回合必玩。
4 記錄結果保存每回合操作、劇本原定總押、劇本承諾總派彩、是否擊殺與決策原因。
5 真實分類只依最終實際倍率放入贏多、贏或輸。
人工智慧可以做預先讀取同一固定種子依法會出現的內容；比較合法路線；依成本與獲利機會停損；必要時手動調整保留。
人工智慧不能做改牌、改魔法卡、改對手牌、改骰面、換種子、為了分類重跑同一結果，或看到結局後重寫先前決策。

三、每次建立新 Boss：三候選抽取

3.1 後端抽取順序

先驗證劇本來源。確認玩家、星級、劇本版本與資料索引；失敗時不建立新 Boss。
三個完整分類各抽 1 個。在當前星級的贏多、贏、輸分類內各自等機率抽取。
以劇本原定總押與劇本承諾總派彩計分。不做類內排名，不挑比較接近目標 RTP 的劇本。
配置 1,000,000 張整數籤。三個候選都必須大於 0 籤，加權期望要符合目標。
依籤數抽中並鎖定。鎖定故事、發布版本、目標 RTP 與抑制簽章；第一次 START 成功扣款時，才把入場費乘上鎖定 RTP 加入對應 Bet 桶並預留原骰獎。
每隻 Boss 獨立抽取：下一隻重新從三個完整分類抽候選；不讀上一隻結果，不讀個人劇本水池，也不因同一玩家曾抽過就排除劇本。
建立失敗就整筆失敗：任一分類沒有可用劇本，或三候選無法合法配籤時，不扣款、不留下半筆 Boss，也不得以零籤建立。

四、目標 RTP 配籤專區｜從三個真實候選算到中籤劇本

本區可獨立閱讀。三個候選已先從贏多、贏、輸三個完整分類各等機率抽出；配籤只使用這三個候選的劇本原定總押與劇本承諾總派彩，不再回分類內挑牌局，也不讀玩家歷史、個人劇本水池或上一隻 Boss。

唯一正式公式鎖定目標 RTP = Q%，80 ≤ Q ≤ 99；出廠 Q=96分數 scoreᵢ = 劇本承諾總派彩 Pᵢ × 100 − Q × 劇本原定總押 WᵢΣ 籤數 nᵢ = 1,000,000；三個 nᵢ 都必須 ≥ 1加權劇本承諾退幣率 = Σ(nᵢ × Pᵢ) ÷ Σ(nᵢ × Wᵢ)等價檢查：Σ(nᵢ × scoreᵢ) ≈ 0Q=96 時正式容許差 0.01 個百分點，即 95.99%～96.01%。其他 Q 以相同公式與容許差驗收。

4.1 後端求籤固定順序

計算三個分數。分數正值表示該候選高於 96% 目標，負值表示低於目標；分類名稱本身不能代替分數。
先檢查能否夾住 0。必須同時存在不大於 0 與不小於 0 的分數；若三個分數全正或全負，這組候選不可能配成 96%，整組重抽。
求連續機率解。在所有能令加權分數為 0 的三候選機率中，選擇最接近中性基準 1/3、1/3、1/3 的解；這只是在多個可行解間固定選法，不是指定分類比例。
轉為 1,000,000 張整數籤。在連續解附近尋找誤差最小的整數組合；三個候選都必須至少 1 籤。
驗收整組。重新用整數籤計算加權 W、加權 P 與 RTP；零籤、總籤數錯誤或誤差超過 0.01 個百分點都整組作廢。
只抽一次 K。K 均勻抽自 1～1,000,000，依贏多 → 贏 → 輸的累積籤區間選中唯一劇本並永久保存。
最常見的錯法：不能把三個候選各自的退幣率直接平均；不能先指定贏多／贏／輸固定百分比；不能讓其中一類拿 0 籤；不能因某一候選較接近 96% 就替換原先等機率抽出的候選。

五、劇本鎖定後如何遊玩

新 Boss 劇本與 RTP 已鎖定等待第一次 START首次調整與入場實付同筆入桶後續實付逐筆 × RTP 即時入桶實際總派彩全額出桶
階段前端後端
建立新 Boss送玩家、星級、BET、版本與唯一請求號；顯示後端鎖定結果。抽三候選、配籤、抽中並鎖定劇本；此時不寫入個人劇本水池。
第一次 START送出開始請求。驗證餘額後原子扣入場費；同筆把有號的「劇本預定派彩 − 劇本預定總押 × 鎖定 RTP」與「入場費 × 鎖定 RTP」加入當下 BET 桶，記入本隻玩家實際總押，並以 encounterId 預留「原骰總倍數 × 鎖定 BET」。
遊玩顯示已接受內容；玩家可自由送出保留、REDRAW、FIGHT、FOLD、CONTINUE 或停止。以操作序號去重；保存劇本原定操作與實際操作是否相同；CONTINUE 與付費 REDRAW 每筆都按鎖定目標 RTP 入相同 Bet 桶。
隨機結果換牌只接收最後被接受的牌；魔法開卡只接收種類，只有金幣卡同時接收實際加成。其餘傷害值到比牌結算才接收。先完成換牌抑制判斷，被拒絕候選永遠不送前端；比牌時依鎖定狀態選正常表或抑制表，抽出本次傷害有效值。
結算表演 Boss 骰獎、Coin Bonus、玩家最終派彩與餘額。使用已落帳水池選合法骰面，再把實際總派彩全額扣除；不得補記押注差額，且整體只結算一次。
魔法卡抽取契約：每回合的候選池固定為十種不同魔法卡，後端依鎖定故事亂數不放回抽出兩種並保存結果。前端必須先用十張牌背表達完整候選總數，再明確標示被抽中的兩張，最後依後端既定順序逐張揭示；前端不得自行重抽、替換或改變魔法卡結果。
完整重播契約：本隻鎖定故事種子、星級、分類、牌局規則版、規劃器版、操作紀錄版、完整抑制參數、抑制政策簽章與故事池簽章。第一次 START 後保存玩家與 Boss 初始手牌 ID、魔法卡種類、後端正常表隱藏值與綁定位；每筆操作保存遞增序號、冪等請求號、操作前後手牌／保留／牌堆／HP、劇本原定操作及實際操作，FIGHT 再保存使用哪張表、抽取亂數、結果索引與最終有效值。相同契約加相同有序操作，雙方初始手牌、魔法卡、換牌與結算必須完全一致；只存種子或只存最後手牌都不完整。
鎖定後不得偷改：不能換劇本、改 Boss 手牌、改對手牌、改劇本種子，或為了貼近承諾結果而直接指定玩家牌。允許的執行期控制只有下一節明定的換牌／最終魔法抑制，以及個人劇本水池驅動的合法 Boss 骰獎補正。
正式前端只收當下公開結果：劇本種子、未來牌序、Boss 未公開手牌、三候選、分數、籤數、中籤整數 K、劇本預定操作、尚餘換牌次數、抑制亂數狀態與個人劇本水池餘額都只留後端。前端每次操作只送請求與序號，不能預載完整劇本後自行結算；劇本節奏提示只能出現在明確啟用的 QA 稽核模式，不得顯示給一般玩家。

六、玩家偏離時的過程抑制

唯一啟動條件抽中劇本 classKey = "lose"而且：成功換牌時，玩家實際保留牌 ID 集合 ≠ 劇本同回合／同平手重發段／同換牌序號的預定保留牌 ID 集合或：該位置沒有預定 REDRAW，plannedRecordMissing = true只比較牌的識別碼集合，不比較顯示順序。劇本路徑已結束、額外和局重發或額外換牌造成無對應紀錄時，不得以空集合冒充劇本要求全換；該次成功換牌直接算偏離。一旦符合條件，自該次換牌候選開始，本隻 Boss 後續永久處於抑制狀態。

抽中贏多或贏劇本時完全不啟動過程抑制；是否擊殺不是啟動條件。本機制不要求玩家路徑重新接回原劇本。

哪些偏離要存：FIGHT／FOLD、提前停止、CONTINUE、換 Boss、換 BET 與每次保留選擇都要保存並標示是否符合劇本；正式預設 deviation-suppression-v5-lose-story-only 只由上方「輸劇本＋成功 REDRAW 保留集合不同或無對應紀錄」啟動。劇本已結束後的合法操作與和局重發照常進行；贏多或贏劇本只記偏離、不啟動本版抑制。

10.3 正式發布

每個正式版本的每星、每種結果分類都必須有 10,000 個可用劇本；全 8 星發布量固定 240,000 個。
自然生成必須持續到最稀少分類也達標，再各格截取 10,000 個；不能複製、補造或改寫劇本。
分類門檻、Boss 參數、魔法機率、規劃版本、索引與稽核資料必須共用同一版本簽章。
完整重播全部 240,000 筆，逐筆檢查 seed 唯一、分類、摘要、操作路徑與跨檔 SHA-256；任一筆失敗整版不得發布。
新 Boss 使用新發布版本；進行中的 Boss 維持原發布版、RTP、抑制簽章與完整房間狀態。換日、回滾及滾動部署不得跨版本還原。

十一、後端實作與資料責任

11.1 跨語言精確契約

優先直接使用現行核心。若必須用其他後端語言重寫，不得改用語言內建亂數、洗牌或近似配籤。以下任一項不一致，都視為不同引擎版本。
uint32 亂數。hash32、mulberry32 全部中間值取低 32 位，右移為無號右移；PRNG 每次先加 0x6D2B79F5，輸出除以 2^32。
固定呼叫順序。Fisher–Yates 由尾到頭，每一步只取一次亂數，交換 floor(random×(index+1))；發牌、魔法、綁定位、爛高牌重抽、和局重發與骰獎順序不得調換。
排序決勝。牌型先比 rank 再逐項比 tiebreak；骰獎依 total、normalSum、multiplierSum 遞增；完全相同保留先產生者，排序必須穩定。
中性連續解。列出可行線與單純形的全部端點，取距離最遠端點對，把 (1/3,1/3,1/3) 投影到線段；相同距離沿用端點產生順序。
1,000,000 整數籤。第一候選掃描連續解四捨五入值 ±96；第二候選由分數式求中心後掃 -3..+3；第三候選取餘數。先比 RTP 絕對誤差，再比與連續解平方距離，仍同分保留先掃到者；任一籤 ≤0 整組重抽。
固定測試向量hash32(20260824,12345,7098) = 553687176mulberry32(0x12345678) 前五個 uint32 = 455919406, 4042750857, 4036713555, 1004527575, 38851746517 星 stateIndex=2 固定骰例 = 普通 [1,3,4,5]、倍數 [2,2,5]、總獎 117文件固定三候選例 = 95,106／403,725／501,169 籤固定向量通過後，仍須把同一發布版 240,000 筆 seed、分類、摘要、操作路徑與跨檔簽章全部對拍；不能只抽樣。
交易／資料後端必存內容失敗時
新 Boss 鎖定玩家、BET、星級、劇本版本、鎖定目標 RTP、三候選 ID、分數、籤數、理論誤差、中籤整數 K、抽中劇本與唯一請求號。版本錯誤或無法配籤時不得留下半筆鎖定。
第一次 START鎖定劇本 ID、START 請求號、實際扣款、鎖定 BET／RTP、劇本預定總押注、劇本預定派彩、有號劇本首次調整、實付入池額、開始前後同桶水池，以及 encounterId 對應的原骰獎預留。扣款、劇本首次調整、實付入池、玩家實際總押與預留必須原子完成；失敗時劇本維持未開始。
CONTINUE／付費 REDRAW操作序號、唯一請求號、實際扣款、鎖定 RTP、實付入池額、入池前後餘額；REDRAW 另存同回合／同平手重發段／同換牌序號的預定與實際保留牌 ID、完整抑制簽章、候選序列與接受結果。重送同一序號只回傳第一次結果；不能重複扣款、重複入池、重新抽值或前進節點。
付費換 Boss更換請求號、舊 Boss 狀態、舊劇本結算、更換費扣款與入桶、新 Boss 鎖定。五項必須同一交易完成；重送只回第一次結果，任一步失敗就全部回滾。
PAUSE／換 BET換注請求號、舊 Boss 完整房間狀態與預留、新 BET、新 Boss 鎖定或恢復。不得結算或釋放舊 Boss 預留；不得搬移三桶餘額。
結算交易鎖定目標 RTP、劇本預定總押／派彩、已落帳劇本首次調整、逐筆實付入池合計、玩家實際總押、實際派彩、本隻預留釋放、同桶其他預留、原骰獎、合法骰面、10%～1,000% 邊界、補正額、個人劇本水池前後與玩家最終派彩。結算不得再補記押注差額；斷線後恢復同一 Boss 與同一結算，派彩只能完成一次。
玩家三桶必須串行：同一玩家可有多隻進行中 Boss，但同一帳務桶的花費、派彩、預留、釋放與補正必須串行或以版本號做條件更新。版本過期不得覆寫；斷線、雙裝置與重送只能恢復同一結果。正式資料置於版本化持久儲存；Redis 只作快取與目前版本指標，清空不得遺失房間、帳本或預留。
