# Boss Duel 劇本池數學模型

更新日期：2026-10-08；對應 `backend-doc-v23`、`rules-v12`、`boss-plan-v13`。完整產品規格及驗證狀態以 `Boss Duel 交接.md` 為主，本文件定義工程數學、帳務與重播契約。

## 1. 版本與資料邊界

遊戲 `frontend-v110`，本機機率工具 `action-tree-v69`；正式產生器 `boss-duel-story-generator-v3` 已產生並發布資料 `natural-story-preset-v17`／`natural-story-summary-preset-v11`，發布識別 `20261008-stage-multiplier-v17`。操作版本 `story-action-trace-v3-stage-assistance`，執行期政策 `deviation-suppression-v6-pool-assistance`，水池版本 `story-budget-personal-pool-v6-stage-multiplier`。

三種資料不可混用：正式目錄的24格是「8星×3分類」；每次START的三候選是當前星各分類均勻抽一筆；玩家三桶B1/B2/B3只負責實際帳務與執行期支援、補正。

正式目錄固定240,000筆，24格各10,000。同一發布版同星級 seed 唯一。分類為 `win: payoutX/spendX≥5`、`push:1≤比例<5`、`lose:比例<1`；1x歸贏、5x歸贏多。`netX=payoutX−spendX`，不能與回報倍率混用。

## 2. 固定種子與自然劇本

離線只使用共用Rules、Arrangement、StoryPlanner及正式產生器。`story-player-policy-v1`只依當下手牌、公開魔法種類、效果綁定、HP、回合與牌堆剩餘數判斷，不能預看未來牌、Boss未公開手牌、骰面、結果、RTP或水池。

互斥候選依完成度、可啟動魔法、同牌雙效果、暴擊、固傷、理牌優先序、核心張數、原始位置與牌ID排序，採第一名並鎖定路線。完成牌不付費換牌；差一張、三條、兩對最多3次；其餘最多2次；Joker使上限減1。免費換牌不占付費次數但推進費率。停止後高牌FOLD、一對以上FIGHT；未死且有回合繼續，沒有STOP_LOSS。

逐筆自然跑完後才分類，不能指定結果再造牌。產線按缺額星級調整批次並補滿每格，出生籤只控制線上遭遇，不參與內容簽章。

## 3. Bet換算與資產門檻

基準劇本保留X倍數：`實付=spendX×Bet`、`自然派彩=payoutX×Bet`、`淨值=netX×Bet`。Bet不得改基準seed、發牌、魔法、玩家路徑、結果分類或配額。

線上會另外受到有限資產、操作偏離、所在Bet桶與歷史水池影響。相同基準seed不保證不同桶的支援、補正及最後玩家結果相同。完整重播需基準劇本加有序操作、政策、資產與帳務快照。

正式Bet清單為1、2、5、10、20、50、100、200、500、800、1000、1200、1500、1800、2000。對星級s使用量測平均實付倍數Eₛ：

`允許Bet={b∈正式清單 | b×Eₛ≤玩家可用資產}`

`Bet上限=max(允許Bet)，空集合時為0`

共用API為 `betLimitForAssets(credits,star)`，成本表 `DEFAULT_AVERAGE_SPEND_X_BY_STAR` 不參與內容簽章。平均花費按96%目標RTP下的可行三候選整數籤權重計算，包含每次START／CONTINUE與付費REDRAW，免費換王費為0。現行母體為 `natural-story-preset-v17`／`natural-story-summary-preset-v11`。

校準版本 `boss-cost-ticket-weighted-v1`：每星獨立使用 `mulberry32(20261008 + star)`，呼叫正式 `drawFullClassStoryCommit()` 15,000 次。每次先依正式政策從三分類抽取並整組重抽至可配，且保留函式內選中候選時的亂數消耗。平均與分位數使用三個候選全部的整數籤權重，並非只取最終抽中者。

令第 g 組第 j 候選的權重 `w[g,j]=ticketCount[g,j]/1,000,000`，成本為 `x[g,j]=spendX`，則 `Eₛ=Σ(w×x)/Σw`。將同 spendX 的權重合併後升序累積；加權 P95 是累積首次達總權重 95% 的最小 spendX，不做分位數插值。P95 是尾端成本描述，不參與平均成本 Bet 上限。

JSON 研究結果保留未四捨五入的 JavaScript 雙精度數值；執行期常數及上表只在最後四捨五入至小數六位。工具保存每星壓縮摘要 JSON 的 SHA-256，確認滿額 checkpoint 研究母體與正式 v11 摘要一致後才能接受校準。修改正式內容或配籤政策時必須重測，不能沿用舊版成本。

本次八星研究母體已逐星與正式 v11 摘要核對一致，未重新抽樣。正式 `naturalSummaries` JSON 的 SHA-256 為 `29bc0d252f12122c079212ec5ad1348eb266c365b05c412003242558867ac423`；這是成本研究的母體指紋，不是整個 JS 檔案的雜湊。

## 4. 血量、星星與自然派彩

定義星數s、初始HP H、剩餘HP h：

`k=min(s,floor((H−h)×s/H))`

第i段門檻為 `H×(s−i)/s`，i=1…s；到門檻即解鎖，最後一段為0HP。一次跨段傷害解鎖所有達成段。星星順序固定一般骰在前、倍率骰在後，不新增另一套骰獎。

`rewardForUnlockedStars(dice,k)` 取鎖定骰面的前綴。N為已解鎖一般骰總和，D為已解鎖倍率骰總和：

- 沒解鎖任何星：Bₖ=0。
- 沒解鎖倍率骰：Bₖ=N。
- 已解鎖倍率骰：Bₖ=N×D。

4星例：一般骰[2,3,4]、倍率骰[4]，0～4星基礎獎依序0、2、5、9、36。這是逐顆原骰解鎖，不是把36均分成4份。

全局金幣倍率M初始1，每張金幣值c均勻取1、2、3、4、5，更新 `M=max(M,c)`。×1無加成並表演碎掉，重複低值不降級、不連乘，最高×5。三條與順子正常傷害倍率均勻×1～×5；四條、同花、葫蘆維持均勻×1～×3。

令Hₚ為整隻累積基礎牌型獎：

`自然 payoutX=(Bₖ+Hₚ)×M`

`payoutParts.boss=Bₖ；hand=Hₚ；coin=(Bₖ+Hₚ)×(M−1)；chain=0`

`originalBossRewardX=unlockedBossRewardX=Bₖ`（基礎已解鎖獎），`originalDice.total`保存完整原骰獎R₀。摘要額外存M、k、baseHandPayoutX。coin欄是為了互斥歸因的倍率增益，不能在乘M後再次相加。

解鎖只保存獎勵權利。未擊殺結束也支付已取得Bₖ與牌型獎，結算一次；PAUSE不派彩。0星可以有牌型獎，但沒有Boss獎，不能無條件支付第一顆骰。

## 5. 三候選分數配籤

當前星贏多、贏、輸完整池各等機率抽一個，不做類內排名、淘汰或挑最接近目標者。Q預設96%，允許80%～99%。候選分數為：

`scoreᵢ=100×payoutXᵢ−Q×spendXᵢ`

`Σticketsᵢ×scoreᵢ≈0；Σticketsᵢ=basis`

遊戲basis=1,000,000；贏多至少30,000、贏至少350,000、輸至少1。先求Σp=1及Σp×score=0的可行線段，再依最低占比裁切，將中性(1/3,1/3,1/3)正交投影後整數化。沒有可行段、誤差超限或最低籤數不符就整組三筆重抽，不得僅替換某一類。

固定範例：三候選各spendX=10，payoutX為50、12、0，Q=96，配籤95106／403725／501169。期望實付10、派彩9.6，RTP96%。這不是固定分類比例。

低於1x的輸劇本也可能高於96%，所以不能僅憑分類名稱假定分數為負。目標RTP控制新Boss基準抽籤期望，不是任意玩家策略或短樣本保證。

## 6. 個人水池事件帳務

三桶：B1=Bet1、2、5、10；B2=20、50、100、200；B3=500、800、1000、1200、1500、1800、2000。玩家資產與水池分開保存，不得跨桶借用。

W=預定payoutX×Bet，Ws=預定spendX×Bet，q=Q/100：

`首次調整 A=W−q×Ws`

`每筆實付入池 Lᵢ=成功扣款ᵢ×q`

`期末帳面 S₁=S₀+A+ΣLᵢ−P`

A只在第一次成功START交易寫入一次；START、CONTINUE及付費REDRAW每筆成功後立即加入L。免費換牌、免費REROLL與扣款失敗入池0。結算只扣P，不另補記實付與預定差額。

使用encounterId保存進行中預留。當前完整獎勵義務 `C=Bet×M×(R₀+Hₚ)`，倍率或牌型獎增加時更新同一筆預留。它與帳面分開，暫停保留，終止結算時釋放。A及L已在帳面，預留與支援判斷都不能再加一次。

## 7. 反向抑制支援及傷害互斥

在成功REDRAW、實際保留集合偏離同回合／同和局段／同換牌序號的劇本集合時評估。沒有對應紀錄保存 `plannedRecordMissing=true`，也算偏離。忠實操作不改補牌。

`V=目前同桶帳面−同桶其他進行中Boss預留`

`可支援 ⇔ V≥C 且 C>0`

本隻完整義務C只比較一次，不能把自己預留先扣掉再要求同筆錢第二次。可用額度及M／Hₚ必須使用當下快照，不得讀劇本未來金幣倍率或未來牌型獎。

可支援時反向使用既有候選接受規則：升級接受100%，同級／下降採原抑制升級接受率；支援最多3組，設定最少2組，末組必收。候選全部從同一原始合法牌堆取樣，被拒絕者不耗牌、不再收費。支援上限獨立於一般抑制上限，避免工具設定1組而失效。

不足額時仍為現行輸劇本偏離抑制：升級預設50%接受，同級／下降100%，最多30候選；工具可鎖定自身出廠參數。負向抑制只限lose，支援不限制原分類。曾支援的本回合FIGHT使用正常魔法值，不能再套負向傷害抑制；新回合清除支援標記。

獨立傷害抑制表：暴擊1～5權重69/25/3/2/1；固傷3～6權重70/25/3/2；所有牌型共用倍率1～3權重80/19/1。表百分比合計100。三條／順子正常值域變成1～5，不代表共用抑制表也同步改為1～5。

## 8. 保護已解鎖星的結算

未擊殺：Bₖ不補正，按原前綴結算 `P=Bet×M×(Bₖ+Hₚ)`。

擊殺：只允許修改最後一顆星的骰面，其他星全部固定。`finalStarDiceOutcomes(originalDice)`列舉最後骰面1～6，維持原骰型及數量，結果還須落在 `0.1×R₀≤R≤10×R₀`。選不超過可用額度的最大合法結果。

`固定牌型派彩 F=Bet×M×Hₚ`

`Boss可用額度 D=帳面−F−同桶其他預留`

`選擇最大合法 R，使 Bet×M×R≤D`

若沒有可負擔結果，選最小合法R，水池可以為負；既有星獎不得因此消失。最終 `P=F+Bet×M×R`。金幣倍率M保持當前值，不另外重抽或補正。0.1～10倍僅數值界線，固定前綴後通常無法遍歷整個範圍。

例：一般[2,3,4]、倍率[4]、M=3、Hₚ=2。未擊殺2星支付(5+2)×3=21；擊殺自然獎(36+2)×3=114。最後骰可改1～6，Boss基礎R僅9、18、27、36、45、54；已解鎖一般骰[2,3,4]不變。總派彩最高(54+2)×3=168。

## 9. 免費預覽與正式房間狀態

`REROLL_BOSS`只允許第一次START前，費用0、入池0，零資產也能操作；仍按出生籤隨機抽王，不提供直接選擇。已START回 `BOSS_ALREADY_STARTED`，已擊殺／關閉也拒絕。預覽更換另計 `previewRerolls`，不計正式挑戰、分類及擊殺率分母。

正式挑戰終止原因為KILLED、BOSS_ESCAPED、USER_EXIT；三者互斥合計Boss總數。PAUSE只是暫停，不列終止統計，不結算、不釋放預留。USER_EXIT不建立新Boss，支付已解鎖部分。靜態Demo沒有完整多房間恢復，不能以Demo切Bet取代正式後端PAUSE。

機率工具極端玩家在多星啟用時，預覽1星有50%免費重抽；只啟用1星時不做無意義預覽循環。主模擬指定Boss數代表成功START數。保留的bossRerollCredits與入池欄必須為0。

## 10. 跨語言精確契約與重播

- hash32與mulberry32中間值均uint32，乘法取低32位，右移無號；mulberry32先加0x6D2B79F5，輸出除以2^32，區間[0,1)。
- Fisher–Yates從length−1遞減到1，每步一次亂數，交換floor(random×(index+1))；發牌、魔法、綁定、初始重抽、和局與骰面維持同一呼叫順序。
- 所有排序穩定；牌型先rank再tiebreak；補正最後骰候選依total升冪。配籤最遠端點同距離時依產生順序。
- 1,000,000整數籤：第一候選掃round(p₀×basis)±96；第二候選由分數方程求理想值並掃offset−3…3，第三為餘數。先RTP誤差、再離連續解平方距離，仍同分保留先掃到者。
- 金額落帳為0.0001 credit的有號64位整數，每事件只捨入一次，0.5遠離0。水池可為負；玩家資產不能透支。
- 固定向量：hash32(20260824,12345,7098)=553687176；mulberry32(0x12345678)前五uint32為455919406,4042750857,4036713555,1004527575,3885174651。
- 7星stateIndex=2、p=0.3141592653、diceSeed=hash32(20260824,7,901)：一般[1,3,4,5]、倍率[2,2,5]、總獎117。此為原骰向量，線上最後骰補正另算。
- 每Boss保存發布／規則／規劃／操作／支援政策版本、RTP、seed、雙方起始牌ID、魔法正常值及綁定、原骰。每操作保存冪等鍵、遞增序號、前後牌堆與保留、費用、HP、解鎖星、倍率、水池／預留快照。
- REDRAW保存偏離、額度判斷、每候選牌ID、升級判斷、接受率、門檻亂數、強制末組及接受結果；FIGHT保存正常或抑制表及最終傷害。相同契約、操作及帳務快照必須可重播。
- 正式前端只收當下公開結果；seed、未來牌、Boss隱藏牌、三候選、分數、預定操作與水池留後端。靜態Demo的qaAudit模式僅供工程驗證。
